# 招聘办理 · 左侧树结构（导航模型）

> 适用范围：`hr/process-audit/process-audit.html`（招聘办理）
> 说明：本文先定义「左侧导航树」的三级层次与流程节点的 4 种典型类型，作为后续「功能说明」章节的骨架。待树结构确认后再展开查询区 / 列表 / 详情 / 操作区。

---

## 1. 树的三级层次

左侧树是一个**三级下钻导航**，从「一个招聘计划」逐层定位到「某个流程节点上的一批人」：

| 层级 | 名称 | 含义 | 是否叶子 | 说明 |
|---|---|---|---|---|
| 第一级 | **招聘计划** | 一次完整的招聘批次（如「2026 年第一批公开招聘」「2026 年高层次人才引进」） | 否 | 计划决定它下面有哪些招聘种类、走哪条流程链 |
| 第二级 | **招聘种类** | 计划下的招考方式（如 选聘 / 先笔后面 / 先面后笔 / 高层次人才） | 否 | 不同种类对应不同的流程节点序列；种类名即流程链名 |
| 第三级 | **流程节点** | 流程链上的具体环节（如 资格审查 / 笔试 / 面试 / 校级审核 / 招聘录用） | **是（叶子）** | 点击叶子 → 右侧加载该环节下、当前页签（待我办理 / 我已办理）的候选人列表 |

**下钻逻辑**：计划 → 计划包含哪些种类 → 该种类按既定流程链展开为节点序列 → 每个节点是一批待办/已办人员。

## 2. 流程节点的 4 种典型类型

第三级叶子节点虽然名字很多，但按「状态签序列 + 操作形态」可归并为 4 种典型类型。类型决定了右侧列表的**状态列、批量操作栏、单条操作菜单**。

### 类型一 · 资格审查型
- **定义**：对候选人资格材料做准入判断的环节，结论为三元（通过 / 退回 / 不通过）。
- **代表节点**：`资格审查`、`资格审查（学院）`、`资格复审`
- **状态签**：`待审核`（单一签）
- **批量操作**：批量通过 / 批量退回（须填退回原因，可指定退回目标环节）/ 批量不通过（或文案「符合 / 不符合」）
- **与其他类型的区别**：无准考证、无成绩，纯材料审核；退回是核心动作，可退回至上一环节重走。

### 类型二 · 考试型
- **定义**：含「准考证 + 成绩」的考核环节，成绩驱动晋级；同一形态复用于多场考试。
- **代表节点**：`笔试`、`面试`、`学院面试`、`校级面试`、`综合素质考察`（成绩评估子类）
- **状态签**：`待确认参加` → `待发准考证` → `待录成绩`（学院/校级面试末态为「录入成绩」；综合素质考察为 `待上传成绩` → `待审核`）
- **批量操作**：确认参加 / 确认不参加、发放准考证、导入成绩（或录入成绩）、通过 / 不通过
- **与其他类型的区别**：存在准考证发放与成绩导入两段式流程；成绩按准考证号唯一匹配；确认不参加即终止该环节。

### 类型三 · 常规审核页面型
- **定义**：通用审核页，录入审核结论 + 意见，可退回上一环节；体检 / 心理测试为其「结果登记」子类。
- **代表节点**：`校级审核`、`委员会评议`、`名单确认（人事处）`、`体检`、`心理测试`
- **状态签**：`待审核`（审核类）；或 `待确认参加` → `待登记结果`（体检 / 心理测试结果登记子类）
- **批量操作**：通过 / 不通过 / 退回（或「通过并下一位」）；体检类为「登记合格 / 不合格」
- **与其他类型的区别**：承载综合审议结论，通常位于流程中后段；不绑定成绩，结论以意见文本为主；可退回。

### 类型四 · 录用环节型
- **定义**：流程终点环节，生成录用结果并衔接调档、公示。
- **代表节点**：`招聘录用`
- **状态签**：`待录用确认` → `已录用`（终态）
- **操作**：录用确认、发调档函、体检确认、汇总表导出、公示发布
- **与其他类型的区别**：唯一终态环节；触发后续人事动作（调档、公示），不再有「退回 / 不通过」的常规流转。

## 3. 原型真实节点 → 类型映射表

以下节点均来自 `process-audit.page.jsx` 的 `NODES_ORDER` / `PROCESS_NODES_BY_TYPE` / `STATUS_SEQUENCES`，按上述 4 类归类：

| 流程节点 | 所属类型 | 状态签序列 | 代表操作 |
|---|---|---|---|
| 资格审查 | ① 资格审查型 | 待审核 | 批量通过 / 批量退回(需原因) / 批量不通过 |
| 资格审查（学院） | ① 资格审查型 | 待审核 | 通过 / 退回 / 不通过 |
| 资格复审 | ① 资格审查型 | 待审核 | 通过 / 退回 / 不通过 |
| 笔试 | ② 考试型 | 待确认参加 → 待发准考证 → 待录成绩 | 确认参加/不参加、发准考证、导入成绩、通过/不通过 |
| 面试 | ② 考试型 | 同上 | 同上 |
| 学院面试 | ② 考试型 | 同上（末态：录入成绩） | 确认参加/不参加、发准考证、录入成绩 |
| 校级面试 | ② 考试型 | 同上（末态：录入成绩） | 同上 |
| 综合素质考察 | ② 考试型（成绩评估） | 待上传成绩 → 待审核 | 上传成绩、通过/不通过 |
| 校级审核 | ③ 常规审核页面型 | 待审核 | 通过并下一位 / 退回 / 不通过 |
| 委员会评议 | ③ 常规审核页面型 | 待审核 | 通过 / 不通过 |
| 名单确认（人事处） | ③ 常规审核页面型 | 待审核 | 批量通过 / 退回 / 不通过 |
| 体检 | ③ 常规审核页面型（结果登记） | 待确认参加 → 待登记结果 | 确认参加/不参加、登记合格/不合格 |
| 心理测试 | ③ 常规审核页面型（结果登记） | 待确认参加 → 待登记结果 | 同上 |
| 招聘录用 | ④ 录用环节型 | 待录用确认 → 已录用 | 录用确认、发调档函、汇总表导出、公示 |

## 4. 树的渲染与交互规则（建议）

1. **叶子徽标**：每个流程节点叶子显示「人数」徽标；超时人员以红色提示（原型已有 `overdue` 计数）。
2. **自动定位**：进入页面默认展开并选中「第一个含超时人员的节点」，否则选中第一个节点（原型 `defaultSelectedKey` 逻辑）。
3. **双页签共用一棵树**：「待我办理」「我已办理」两个页签复用同一棵三级树，仅右侧列表数据不同（原型 `planTree` 共用）。
4. **类型可着色**：可在树上以类型色区分节点（资格审查=蓝 / 考试=橙 / 常规审核=青绿 / 录用=紫），帮助人事处快速识别环节性质。
5. **计划→种类依赖**：种类列表由所选计划决定（如高层次人才计划追加「部门初试」节点），树应随计划切换动态重建。
