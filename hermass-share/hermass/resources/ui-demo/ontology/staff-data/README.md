# 教职工数据分区（staff-data）

深职大真实教职工基础数据与扩展信息，整理为本分区，作为全系统人员统计的**唯一数据源**。

版本 `0.4.0` · 数据快照 2026-09-04

---

## 一句话说明

**系统里任何地方要统计人员数据，都从这里取口径和数字，不要自己算。**

## 怎么引用

### 场景一：页面/报表要显示人员统计数字

读取 `statistics/`，**不要查明细后自行计算**：

```jsonc
// overview.json 结构
{
  "headcount": { "total": 4512, "active": 3262, "byStatus": [...] },
  "activeProfile": { "byStaffCategory": [...], "byTitleLevel": [...] },
  "keyIndicators": { "fullTimeTeacher": 1522, "phdCount": 1102 }
}
```

### 场景二：不确定"在职人数"该怎么算

查 `statistics/statistics-spec.yaml` 的 `population` 段。默认口径是 `active`（在职 3,262），不是总记录数 4,512。

### 场景三：要按部门拆分统计

`statistics/main-distributions.json` 的 `crossByDepartment`，已按部门 × 类别/身份/职称/学位/岗位交叉预计算。

### 场景四：要知道某个字段是什么含义、能不能用

查 `data-dictionary/main-table-fields.yaml`，每个字段标注了类型、敏感度分级、填充率、是否统计维度。

## 统计口径要点（三条最容易错的）

1. **默认分母是在职 3,262，不是 4,512。** 4,512 包含离职 632、退休 590、其他 19、死亡 9。

2. **扩展表统计人数必须按工号去重。** 例如学习经历 8,196 条记录只对应 4,006 人；政治面貌 3,901 条对应 3,845 人。只有统计"事项数"时才用记录数。

3. **"（未填）"必须作为独立分项展示，不能丢掉。** 教职工类别有 93 人未填、职称等级 233 人未填，丢掉会导致分项加总对不上总数。

完整规则见 `statistics/statistics-spec.yaml` 的 `rules` 段（R1–R8）。

## 数据问题（使用前必读）

| 问题 | 影响 | 建议 |
|---|---|---|
| **辅导员口径不一致** | "是否辅导员=是" 151 人，"教职工类别=辅导员" 152 人，差 1 人 | 确认以哪个为准 |
| 班主任经历仅 6 条（4 人） | 与主表"是否班主任"有值的 1,438 人严重不匹配 | 确认是否为完整导出，当前不可用于统计 |
| 双师主表 1,095 vs 双师表 1,124 | 差 29 人 | 核对口径 |
| 教职工类别 93 人未填 | 分类统计总数对不上 | 人事处补全 |
| 职称等级 233 人未填 | 职称结构覆盖不完整 | 无职称应标注"未评定"而非留空 |
| 扩展表孤儿记录最多 24 条 | 跨表关联丢失 | 补主表或清理 |
| 字典脏数据 | 如 "[电工]未定义"、"[取得途径取得途]未定义" | 清洗后再用于正式统计 |

## 数据安全

⚠️ **本分区不存放原始明细数据。**

原始数据含 4,497 条身份证号、3,183 条银行卡号、3,359 条社保号，属于受限级信息，保存在 `/Volumes/WD/下载/深职大基础数据和扩展信息数据`，**不复制进本目录、不提交代码仓库**。

本分区存放的内容：字段定义、实体映射、脱敏后的聚合统计结果、治理规则。

使用约束详见 `governance/sensitive-fields.yaml`：

- **受限级 17 个字段**：禁止进入检索、日志、导出、统计
- **敏感级 35 个字段**：仅允许输出聚合值，禁止输出明细
- **内部级 79 个字段**：可正常查询统计

## 维护

原始数据更新后，需重新生成本分区 `statistics/` 下的 JSON 文件。生成逻辑基于源文件实算，不含人工估算值。

`statistics-spec.yaml` 中的所有数值均为源数据实算结果，修改该文件前请重新核对数据。
